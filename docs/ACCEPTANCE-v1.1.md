## 新增重点用例

- API Key 不出现在配置响应、`state`、SQLite、备份中；新的 `CloudAI` 实例没有 Key；换服务商/清 Key 正确使授权失效。
- 保存连接和生成预览均不调用外部 API；需要严格布尔确认；授权一次性、过期或变更配置不可再用；在途请求不会重复发送。
- 配置持久化失败时，不把新服务商密钥错误绑定到旧端点/旧授权（故障注入测试）。
- 默认不发档案/饮食信息；饮食 opt-in 不附姓名、联系方式或健康问题记录；档案 opt-in 展示实际摘录；长说明检索限制明确；危险表现不遮掉事实摘录。
- 图片 Base64 与原字节一致；没有视觉确认被拒绝；OpenAI PDF 负载符合本版契约，其他提供者的 PDF 直传被阻止；超大/过长内容拒绝；来源删除后拒绝发送。
- 公网 HTTPS/443/端点格式验证、DNS 私网或混合解析拒绝、固定地址传输、不跟随重定向、不自动重试、服务商错误不回显 Key。
- 畸形模型输出不能成为合格草稿；草稿不会修改临床记录或自动确认分类；实际饮食与模型猜测分开、有版本冲突保护。
- v1 数据库升级及 v1/v2 备份兼容；科室关联和草稿保留；错误来源哈希/元数据、错误科名/版本/重复 ID 拒绝；草稿引用原件时拒绝删除。
- HTTP 覆盖配置 → 预览 → 确认 → 草稿 → 实际饮食 → 删除/清密钥，以及报告分类确认和跨站/无令牌请求。
- 前端十一页面空状态、四种助理模式、模型内容/来源转义、自定义科室保留、跨科归属、待确认标签和正确隐私文案。

## 明确尚未验证

- 未提供真实模型 Key，没有对 OpenAI、百炼、硅基流动执行付费推理；模型兼容性、配额、地区可用性和真实识别质量须在用户自选服务中验证。接口地址/负载参考官方文档，不把“协议测试通过”当“模型全兼容”。
- 图片/PDF 字节负载及失败路径通过测试，但没有真实早餐照片或医院报告的识别准确率数据，也没有医学专家审查。
- 本地没有 OCR 引擎；没有 DICOM 像素诊断、疾病概率、处方生成、治疗性食谱、全库加密或多设备同步。
- 本机 Ollama 仍只经过模拟响应测试；没有新安装模型推理。
- 没有运行 Windows/Linux 真实环境、远端 GitHub Actions、正式渗透测试、全 WCAG/屏幕阅读器认证、海量数据或断电故障测试。
- 99 项测试不穷尽所有错误。AI 自评置信度不是校准概率，结构化输出不是医学事实。
