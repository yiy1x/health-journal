# GitHub 发布检查清单

面向仓库所有者。当前版本为开发预览；本清单不等同于临床、合规或第三方安全认证。建议先私有仓库验收，再决定是否公开。

## 代码和数据分离

- [ ] 真实档案目录位于仓库之外；演示、测试及截图均为合成内容。
- [ ] 检查 `git status --short --untracked-files=all`、`git status --ignored --short`、`git diff --cached`；不要无审查执行 `git add .`。
- [ ] 检查新增 PDF/JPG/PNG/TXT、数据库、ZIP、日志、截图、导出的上下文和任何私人目录路径，不只依赖密钥模式扫描。
- [ ] 检查所有已有 Git 历史、分支、Release、CI 产物和附件；`.gitignore` 不能移除已经提交的数据。
- [ ] 若曾泄露真实 Key，先在服务商撤销/轮换，再处理历史清理；保留必要事件记录但不继续公开秘密。

## 许可和文档

- [ ] 确认 LICENSE 的 MIT 文本和版权归属；新增依赖/图像/数据必须有兼容许可和必要归属声明。
- [ ] README 的版本、启动、升级、备份限制与当前代码一致；链接全部可用。
- [ ] 详细免责声明、PRIVACY、SECURITY 描述实际行为；未宣称零 Bug、临床效果、监管批准或自动合规。
- [ ] 确认支持范围及已知未通过验收事项，没有把历史报告当作新版本验证。
- [ ] 不把真实报告或第三方未经授权的数据混入代码 MIT 许可范围。

## 测试和打包

```bash
python3 -m unittest discover -s tests -v
node --check health_journal/web/app.js
node --test tests/web*.test.cjs
```

- [ ] 在目标操作系统和受维护 Python 上执行；确认 GitHub Actions 的实际结果，不仅检查 YAML 存在。
- [ ] 独立现代浏览器核验 12 个页面、子路由刷新/返回、未保存表单的继续/放弃、Escape 关闭、后台分析切页、不同标签页冲突。
- [ ] 验证程序停止再重启后资料仍在、Key 不在；验证 ZIP 往返和升级前目录副本可恢复。
- [ ] 390 px/1440 px、键盘操作、长中文、空档案、报错状态和打印摘要重新抽查。历史截图不是新变更的验收证据。
- [ ] 模型测试默认 mock；真实接口验收只用明确同意的无敏感样本，核对费用与数据政策。
- [ ] 在空目录检查 Wheel 的静态资源、版本、MIT 许可，不包含真实资料、测试夹具、旧 build 缓存或本机 Key。
- [ ] 打包后从安装包启动一次；发布包而非整个 `dist/`，附校验和、版本说明和已知限制。
- [ ] 手机真机验收：相机取消/重拍、相册/文件选择、HEIC 拒绝、竖横屏/键盘、离线重开、系统实际下载、加密备份在另一设备解密合并。
- [ ] 手机静态产物只包含导出器允许资源；不含 `.hjvault`、`.hj-transfer.json` 或数据库。部署 HTTPS 和可信独立来源，更新 Service Worker 缓存版本，不清理站点数据升级。
- [ ] 明确告知当前只是原件手动互传，不把桌面临床记录、餐单、分科确认或 API Key 宣称为已自动同步。

## GitHub 配置

- [ ] 由用户确认目标 GitHub 账号、仓库名称、可见性和实际远端 URL；不要猜测维护者身份。
- [ ] 启用可用的私有漏洞报告、secret scanning/push protection；可用性取决于账号和仓库方案，不声称默认已启用。
- [ ] 发布不含敏感内容的联络渠道；未建立私有渠道前只接受不含利用细节的联络请求。
- [ ] 限制 Actions 和仓库权限；不使用带秘密的 `pull_request_target` 执行不可信 PR；审查第三方 Action 版本及是否固定到已验证 SHA。
- [ ] 分支保护、必要 Review/CI 检查由维护者配置；它们不是本仓库文件能自动保证的功能。

## 升级与回滚

1.5 增加 `food_entries` 并升级 schema v4；有独立日记的 ZIP 使用 v4，恢复支持 v1–v4。照片沿用附件引用；删除日记不删除原件。升级前停服备份，已有真实库不由源码合并流程读取或迁移；旧版不能原地打开新库。发布需保留 GitHub 已有历史及 CI/异步测试修正，参见 [RECONCILIATION.md](RECONCILIATION.md)。

1.4 使用 schema v3：升级前先停服做私密备份。新版本新增独立可穿戴样本/批次/引用，不清空临床记录；旧版不能原地打开新库。含设备数据的便携 ZIP 使用 v3，无设备数据时仍 v2；只有当前版能恢复新格式。发布前重测 Apple 文件/XML 安全、时区、单位、来源重叠、批次删除、备份/原值校验和旧库升级。`.health-import-*` 是敏感临时目录，不得入 Git/Release。

1.3.1 将新档案姓名和饮食偏好改为未填写，不迁移或清空旧资料。新备份可能包含空称呼及 `diet: unspecified`，旧程序不保证能读，应使用当前版本恢复。初版交付仅打包代码和静态资源，排除 `.local-personal-v1`、所有旧演示库及凭证；新用户按 README 普通启动进入空档案。

1.3 发布还须检查 `.codex-connection`、`auth.json`、CLI 日志和账号邮箱均未进入产物；运行 Codex 模拟协议测试，真实登录必须由使用者完成，不在 CI 放 Token。CLI 本身不随本项目分发，用户遵循其单独许可/条款。新功能细节见 [CODEX.md](CODEX.md)。

升级前停止应用，完整复制资料目录并标注所用程序版本。回滚使用对应旧程序和升级前副本，不要对新库原地降级。完整目录复制可能包含 Codex 凭证和 Apple 临时导入文件，必须私密保存；便携 ZIP 不含凭证。手机备份格式独立，不能代替桌面 ZIP。当前验证范围见 [1.4 验收报告](ACCEPTANCE-v1.4.0.md)。

若遇到数据异常，先停止继续写入、保留原目录和相关版本，使用复制出来的合成或已脱敏最小复现排查；不要“修复”时删除唯一原件，也不要把私有库直接发到 Issue。
