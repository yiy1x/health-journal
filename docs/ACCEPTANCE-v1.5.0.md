# 1.5.0 日常手记与代码统一验收

日期：2026-11-25。源码 1.5.0；SQLite schema v4，有独立饮食日记的 ZIP 为 v4；恢复兼容 v1–v4。手机独立资料版保持 1.2.1，没有自动结构化日记同步。

## 自动化结果

本轮最终套件 **341 个不同测试：228 Python + 113 Node**。Python 3.9.6、3.12.14 分别执行完整套件，重复执行不重复计数。CI 的其它平台结果应以该提交的真实 Actions 为准，不以配置存在代替。

相对 1.4 的 312 项，新增 19 个饮食/日概况后端测试、2 个 HTTP 测试、7 个前端状态测试，以及 1 个临时 SQLite 连接关闭回归。原有核心、云模型、Codex、Apple 导入、手机加密/互传均保留。合并后保留 GitHub 的手机异步等待修正，而非把测试改回更易偶现失败的固定 tick。

重点覆盖：

- 不需要餐单/模型即可记录实际饮食；新库仍空白，默认不假设饮食偏好或成人适用。
- 相同 UUID/内容重复提交只写一次；不同 UUID 的同内容可分别保留；旧版本编辑/删除和并发写入拒绝覆盖。
- 时间、日期、未来用餐、餐次、长度、类型、原件存在性/哈希校验；SQL/HTML 文本不执行。
- 日记引用保护照片，删除日记仍保留原件；日志不含正文；独立日记不隐含加入 AI 摘录。
- 日期范围、当天缺失值、来源选择、实际饮食与设备同日显示。
- v4 日记/照片备份、日记+Apple 联合备份恢复、篡改和重复/缺失引用拒绝、占用库保护、v3 数据库升级保留原资料。
- URL 日期校验、默认今天而非最近导入日、乱序响应/切页丢弃、表单版本绑定、重复保存、失败保留输入、图表缺失不连线。
- Apple 临时 SQLite 连接在解析和提交后显式关闭，避免 Windows 文件句柄导致清理失败。

## 发现及修正

- 原来实际饮食依赖餐单/AI，新增独立表与入口，不用“关闭营养安全限制”来凑功能。
- 日期切换开始前先更新模块日期与清空旧快照，避免一帧把旧日记显示在新日期标题下。
- 已经成功保存但刷新失败时明确说已保存，不把用户引向重复新增。
- 原件列表计数纳入独立日记引用，删除保护与界面含义一致。
- 保留既有 SQL/备份/模型边界，不新增公网访问、隐含 AI 共享或明文浏览器持久化。
