# 第一版交付范围

本文保留 v1.0 的原始交付范围。当前 v1.1 在此基础上增加可选云端模型、图文草稿和多科目录，差异见本文末尾及 README；这里的“不做 OCR”指原版/本地引擎，不否认后续可选的视觉模型整理。

## 设计

产品名：知己 · 健康手记。主体是个人档案，不把聊天作为首页，也不模拟医疗诊断。

- 色彩：墨蓝 `#253c58`、松绿 `#397269`、雾白 `#f4f7f9`、白 `#ffffff`、提示琥珀 `#986021`、警示红 `#a94343`。
- 字体：系统中文字体（PingFang SC / Microsoft YaHei）；标题适度加粗，不依赖外部字体和 CDN。
- 桌面：固定目录 + 宽工作区；首页以健康记录概览、趋势与近期事项构成。手机版目录收起为横向导航。
- 来源、待核对、一般膳食和就医提醒使用明确文字，不单靠颜色。
- 不用装饰性渐变、无含义分数或“健康度 98 分”。

## 技术与边界

Python 3.9+ 标准库 HTTP 服务，SQLite，本地不可变附件，原生 JavaScript/CSS。没有第三方运行时依赖，无需 npm 构建。只监听回环地址，拒绝跨站 API 请求，使用每次启动随机令牌。数据默认保存在仓库外，开发演示保存在被忽略的独立目录。

功能：档案 CRUD、附件导入下载、科室时间线、指标趋势与可比性保护、症状/疾病状态区分、用药有效期、随访完成、受约束的一般餐单、实际饮食记录、基于事实的本地助理、可选本机 Ollama、就医摘要、ZIP 备份与空库恢复。

不冒充完成的功能：扫描报告 OCR、医学诊断、自动处方、治疗性营养计划、后台系统推送、多设备同步、应用级全库加密。扫描 PDF 和图片可保存并人工摘录；文本文件可读取但不自动转为已核实医疗事实。

## 验收

- 单元测试验证输入校验、数据库修改冲突、来源关系、用药日期、餐单过敏限制、助理事实检索和备份恢复。
- HTTP 测试验证令牌、Origin/Host、路径、文件签名、上传限额、导出恢复、错误响应。
- 浏览器验证演示首页、记录创建/编辑、搜索筛选、指标、附件、饮食、助理、设置、手机布局。
- 公共仓库只包含代码、说明和合成数据生成器；无个人病历和凭证。

## v1.1 增量实现

- `departments.py`：55 科、7 组，文件名/文字关键词建议，最多 12 个待确认关联，沿用已有自由科名。
- `cloud.py`：OpenAI-compatible Chat Completions、公网 HTTPS/TLS/DNS 保护、服务端内存 Key、一次性 10 分钟授权快照；文字/图片/受限 PDF。
- `analyses` 表：结构化食物/报告/问答草稿，来源哈希/发送上下文/模型版本标识（用户填写的模型 ID）；不生成临床事实；实际饮食由人单独填写。
- `document_routes` 表：多科关联与版本冲突检查；原件仍是唯一副本，不按科室复制。
- 数据库及备份升级到结构 v2；恢复兼容 v1/2。升级前要求独立备份，不承诺原库降级。
- 十一页面导航；助理采用任务页签、输入/结果双栏、历史草稿和来源折叠区；科室目录采用文件夹卡片、身体部位搜索和有资料筛选。
- 新增合成模型/传输/授权测试与 `tests.browser_fixture` 离线浏览器夹具。夹具不在生产包内，没有生产模式的“假成功”开关。

## v1.1.1 可靠性修订

- Hash 路由解析集中在 `routeState`，子页面使用白名单参数，未知路由回退总览。内置科室使用目录序号、自定义科名通过一条现存记录 ID 定位；删除该记录后可回退目录，不是永久跨库链接。
- 表单用 `data-version` / `data-revision` 绑定读取时版本；未保存输入/保存中标记阻止后台重绘，按递增请求序号丢弃乱序快照。
- 页内独立 `leave-modal` 不覆盖原编辑对话框，继续编辑/放弃输入后分别保持或释放脏状态；关闭浏览器的保护仍由浏览器自行决定。
- 服务端拒绝歧义 HTTP/JSON 输入，关闭连接复用；附件大小与摘要一起校验，严格 v2 恢复必要字段，不使丢失资料静默变成空集合。
- 重启回归验证档案、原件、分类、草稿、实际饮食和餐单仍在本机，API Key 与会话令牌按设计失效/更新。
- 本次验证能力和残留限制见 [审查报告](AUDIT-2026-11-13.md)。

## v1.2 手机增量实现

- `web/phone/` 为独立静态资料应用，`core.js` 负责格式、哈希、加密、合并，`db.js` 负责带版本 CAS 的 IndexedDB 单事务快照，`phone.js` 负责导入/查看/锁定和明确导出界面。
- `export_phone.py` 仅导出显式允许资源、MIT 许可和公开科室目录；无账号、遥测、数据中继、云模型或个人数据库复制。
- `sw.js` 的精确 URL 允许列表只缓存静态应用壳；不抢占当前打开的旧版本，关闭所有旧页后更新。部署新资源须更新缓存名称。
- `transfer.py` 定义独立原件互传格式，限制文件数量、大小、编码和哈希；`Store.merge_documents` 整体校验、事务新增、不修改已有同哈希文件或结构化记录。
- 桌面增设五项底部导航/更多菜单、四种导入方式、粘贴文字、逐项进度、失败重试和手机版资料列表。原本 11 个功能页面均可从“更多”到达。
- 手动互传不复制结构化诊疗记录，不传播删除；自动同步、恢复密钥和手机版 AI 等明确保留为后续架构任务。详见 [手机与多端说明](MOBILE.md) 和 [本版验收](ACCEPTANCE-v1.2.md)。
