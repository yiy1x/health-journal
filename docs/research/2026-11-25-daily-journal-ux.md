# 每日活动与饮食统一：检索、设计与本地化决策

日期：2026-11-25。目的：从“Apple 数据表旁附上饮食文字”改为真正便于日常记录的页面，而非只更换颜色。

## 检索方法与证据边界

按用户要求尝试了 Google 查询 `Apple Health food diary local first meal logging daily dashboard UX`。Google 返回防自动化/脚本跳转页，**没有把它当作成功的搜索结果或绕过限制**。随后读取公开的一手官方页面与开源 README/使用说明。Cronometer 支持文档两次连接未成功；未采用其不可核实细节。Apple 文档初次猜测路径 404 后，从真实页面给出的 Markdown 链接读取正文，不把 404 当作内容证据。

没有登录第三方账号、提交个人信息、读取真实健康资料，未复制第三方截图或源码。

## 已读取来源与实际吸收内容

### Apple 图表指南

[Charts · Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/charts)（[Markdown 正文](https://developer.apple.com/design/human-interface-guidelines/charts.md)）说明：有效图表应突出少量关键信息、提供准确轴/单位和可访问性说明；日步数等累计值适合柱状图；紧凑环境要留足绘图区；不能要求用户交互才能看到重要信息。

落实：日概览先给选中日期值；七日柱图保留零基线/时间，另有数值表；缺失不连线、不生成假曲线。不把餐次记录变成“营养达标分”或步数兑换热量的圆环。

### Apple 多来源与权限

[管理健康数据和来源](https://support.apple.com/en-us/108779) 说明 Apple 内部有来源优先级；[HealthKit 用户隐私](https://developer.apple.com/documentation/healthkit/protecting-user-privacy) 说明逐类型权限与无数据/拒绝读取不可简单区分。

落实：保留 1.4 的不盲目相加规则，日卡与趋势明确选择来源；默认今天，不把最新导出日冒充今天。没有数据不标成 0 或正常；没有引入 Apple ID 登录或实时同步的虚假承诺。

### Waistline 的逐日日记和本地数据思路

[Waistline README](https://github.com/davidhealey/waistline)、[用户指南](https://github.com/davidhealey/waistline/blob/master/FAQ.md) 描述按日/时段的饮食日记、本地食物信息和导入导出。README 明确使用 GPLv3，并提醒存储不可能保证绝对安全。

落实：按早餐/午餐/晚餐/加餐组织真实记录，创建入口不依赖餐单或模型；备份是核心功能，不把本地当永不丢失。仅吸收公开产品思路，**未复制 GPL 代码、组件、图片或营养数据**，不添加条码联网搜索或热量数据库。

### W3C 和浏览器存储

[WCAG 2.2 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 讨论最小触控目标与间隔；本实现对主要手机操作采用至少 44px，不声称已做完整 WCAG 认证。

[MDN 存储配额与清理](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) 说明按来源存储、默认 best-effort、持久化请求与用户清理/容量限制。

落实：电脑主档案继续使用 SQLite/附件目录，不改成易误清理的 localStorage；手机独立加密 IndexedDB 的边界单独写清。不能把电脑网页响应式适配说成手机已经同步数据。

## 关键产品问题与改造

| 原有问题 | 本轮改造 |
| --- | --- |
| 记实际饮食常需要先生成餐单或先做 AI 分析 | 独立 `food_entries`，不需要个人膳食适用确认或模型 |
| 以数据导入说明和长表格为主，日常记录入口深 | 日期导航 + 四餐卡 + 当日活动，管理内容折叠 |
| 当前视图与最近导出日容易混淆 | 默认今天、显示数据截止日、显式跳转最近记录日 |
| 身体指标和实际饮食在不同入口 | 同日页面统一读取；历史餐单实际记录/AI 旁人工备注保留来源 |
| 照片、文字与事实关联不清 | 可拍照/相册或关联原件；文字自填，照片不自动解读 |
| 所有内容都放进长数据表，手机难操作 | 小屏先步数摘要、再四餐卡；表格折叠、主要触控入口加大 |
| “本地”可能被误读成加密或永不丢失 | 显示 SQLite/附件、磁盘加密提醒、备份入口、电脑与手机的不同位置 |

## 视觉取舍

沿用项目的系统中文字体和低干扰医疗记录基调，主导航从墨蓝调整为深松绿；整体浅灰绿背景、白色表单，四餐图标使用低饱和不同色但保留餐次文字。主标题、主要操作、选中日期和步数有明确层级，避免整页同等重要的说明卡。

桌面左侧“好好吃饭”，右侧“当日步行＋睡眠/心率/距离”；手机将步行摘要放到四餐前面，确保不滚到页底才能看到手表信息。空态不填演示值，不把未记录当作未吃。真实数值和来源说明优先于装饰；没有远端字体、脚本或图片服务。

## 技术及安全决策

新建独立饮食表而不是塞进 AI 草稿：保证没有 API Key 也可用，删除 AI 草稿不连带删除新日记。客户端 UUID 提供重复提交幂等，版本检查保护跨标签编辑；照片继续由现有附件库校验和保存。备份新增 v4，完整保留日记与原件引用；不能忽略新表继续导出一个看似完整的旧备份。

没有根据步数自动加减进食量，没有把同日关联写成因果。疾病/治疗建议仍交由专业人员。本次属于界面/记录与可靠性改进，不是临床效果研究。
