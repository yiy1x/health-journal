# Apple 健康与 Apple Watch 数据导入

版本：1.4.0。日期：2026-11-22。适用电脑本地档案；不登录 Apple ID，不请求 iCloud Cookie，不提供实时 HealthKit 同步。

## 怎么用

1. iPhone 打开 **健康 → 摘要 → 头像 → 导出所有健康数据**。导出由 Apple 完成，可能需要等待。
2. 通过自己控制的方式（例如 AirDrop、文件传递）放到运行本应用的电脑。导出包含敏感信息，不要上传 GitHub、聊天群或公共网盘。
3. 应用左侧 **日常健康 → 导入 Apple 健康**，选择 ZIP 或解压后的 HealthData 主 XML；支持中文名称。
4. 本机后台解析后显示预览。检查有效、重复、无效和不支持类型；选择指标与结束日期范围，勾选本人资料确认，再保存。
5. 选择指标与设备/来源、日期范围，查看每日趋势；点击“查看样本”检查原值、单位、时间、设备和手工录入标记。
6. 在“饮食计划”记录实际吃了什么，再回到“日常健康”查看同日回顾。它不把未吃的计划或 AI 猜测当作真实用餐。
7. 需要手机查看时，可明确确认后导出当前回顾 TXT，在手机资料版作为普通 TXT 导入加密保存。**这是静态回顾，不是原始样本同步。**

Apple 官方说明：[导出 XML](https://support.apple.com/zh-cn/guide/iphone/iph5ede58c3d/ios)、[来源和优先级](https://support.apple.com/en-us/108779)。

## 本轮支持的 18 类数据

| 指标 | 标准展示单位 | 日值方式 |
| --- | --- | --- |
| 步数 | 步 | 同来源、不重叠区间求和 |
| 步行与跑步距离 | km | 同来源、不重叠区间求和；m/mi 转换 |
| 心率、静息心率、步行平均心率 | 次/分 | 样本算术均值，非时间加权 |
| HRV（SDNN） | ms | 样本算术均值；s 转换 |
| 活动能量、静息能量、已记录摄入能量 | kcal | 分开累计；kJ 转换，不计算热量缺口 |
| 锻炼时间 | 分钟 | 不重叠区间累计 |
| 爬楼层数 | 层 | 不重叠区间累计 |
| 体重 | kg | 结束时刻末次记录；lb 转换 |
| 体脂率 | % | 末次记录 |
| 血氧饱和度 | % | 样本均值 |
| 呼吸频率 | 次/分 | 样本均值 |
| 已记录饮水 | mL | 同来源累计；L/美制液体盎司转换 |
| 睡眠 | 小时 | 同结束日、同来源，睡着区间取并集 |
| 体能训练 | 分钟 | 保留训练类别与报告时长；重叠则不汇总 |

Apple XML 中体脂/血氧的 `%` 值按比例处理，例如 `0.98` → `98%`。不会猜测 `98` 实际想表达 `0.98`；不符合单位和边界的项记为无效并在预览说明。标准化值与**导出原始值/单位**同时保留，不重写源文件。

未覆盖类型会统计并列出，不静默说“全部健康数据已导入”。不导入姓名、生日、血型、生殖、临床病历、药品、GPS 路线、ECG 波形、通知、ActivitySummary 或训练的嵌套路径/统计；用户已有基本档案不被覆盖。若某设备本身没测量或权限不允许，导出也不一定含相应数据。

## 为什么数值可能与“健康” App 不同

- Apple 内置 App 可按用户配置的来源优先级处理重叠。文件导出无法可靠重建此设置，本应用**不声称复刻 Apple 总量**。
- 来源使用名称和设备描述（去掉易变的内存地址）识别，来源版本另存。无法辨别设备时不擅自合并；设备描述/软件变化可能表现为新来源。
- 多来源同一日先留空，选择一个来源后统计；同来源累加记录重叠或同一瞬时出现冲突也留空，可查明细。
- 末次测量同一时刻有多个不同值则留空，不任选一个。
- 日期按**结束时间自带时区的日历日**。跨日样本整体归结束日，不假设样本均匀分布而拆分步数或热量。
- 睡眠不是临床分期或夜间会话重建。按每段样本结束日统计；跨不同结束日的分期与总段可能分落不同日期，可能与 Apple 按睡眠日的汇总不同。不要跨日直接相加后当作精确睡眠总时长。
- 睡着仅包含 asleep/core/deep/rem；awake/in_bed 保留但不算睡着。日内阶段可能重叠，各分期并集不可直接相加。可在样本明细核对类别。
- 心率等为已收到样本的均值，不代表全天连续测量；不同采样频率会影响数值。
- `—` 表示缺失或冲突，真实 0 才显示 0。日值均值只基于有效日，不插值，不做正常/异常医学判断。

## 饮食如何联系起来

同一日期展示指标日值和人工实际饮食；餐单里未勾选/未备注的计划、AI 食物识别草稿不自动进入实际饮食列。手表活动能量是估算，摄入可能漏记，不能相减得到可靠的“应补多少能量”。

本模块不会自动改餐单、增加运动目标、计算健康评分、判断疾病、开处方、建议停药或给出治疗膳食。缺失不代表正常；不舒服时应及时就医。即使出现同日变化也不能由此推出因果。

## 存储、备份和删除

- 样本保存在电脑 SQLite 独立表 `wearable_samples`；批次保存在 `wearable_batches`，引用在 `wearable_members`。不混入检验/就诊表。
- 预览前原 ZIP/XML 暂存到本资料目录 `.health-import-*`，解析结束即删除这份临时上传副本。原件不会永久写入附件目录，**用户应自行保留原 Apple 导出文件**。
- 预览 SQLite 最多保留约 30 分钟；取消、确认后清理。正常停服也清理，强杀/断电可能残留临时目录；停服核对后再清理，不是安全擦除。
- 保存是事务性的，只保留选定类型及日期范围；不接受后台模型/外部资料指令。
- 同文件+同范围再次导入返回已导入；文件更新或选不同范围，样本仍按标准化内容去重，新批次可共同引用同一份样本。
- 移除批次需确认；只有没有其他批次引用的样本会删除。不会改 iPhone/Watch 健康库，也不删除饮食或临床记录。没有远端删除传播。
- 桌面、临时文件及导出 TXT **没有应用层加密**。启用磁盘加密、锁屏、访问限制；不要把資料目录同步到公共位置。
- 设备数据不自动进入模型的“附带档案摘录”。若自行将 TXT 回顾作为附件发送给模型，适用既有逐次外发确认与服务商政策。
- 桌面完整便携 ZIP 中有设备数据时升级为备份 v3，新增带 SHA-256 的 `wearable.jsonl`；无设备数据仍导出 v2。恢复支持 v1/v2/v3，仅新空档案可恢复；检查样本原值转换、哈希和批次引用后事务写入。
- 旧应用不能读取 schema v3 数据库/备份 v3。升级前停服备份；不要原地降级。完整目录复制还可能包括 Codex 凭证，需要私密保存。
- 手机原件互传不含这些结构化样本；TXT 静态回顾可以作为原件导入，不能当成完整备份。

## 限额和错误处理

| 限制 | 当前边界 |
| --- | --- |
| 单个上传 | 256 MiB；ZIP 或主 XML |
| 主 XML 展开 | 1 GiB |
| XML 一级条目 | 500 万；有效样本最多 100 万 |
| 来源 | 每个预览最多 200 个 |
| ZIP | 20000 个条目、最多扫描 20 个 XML；恰好一份主 HealthData |
| 上传 / 解析 | 各有 180 秒截止检查；I/O/调度和清理可能增加少量耗时 |
| 长期存储 | 100 万样本、200 批次、200 万引用 |
| 视图 | 最多 366 日；明细每页 50 条 |
| 便携设备备份 | 最多 40 MiB JSONL；整个 ZIP 的原有 60 MiB 展开/64 MiB压缩上限仍适用 |

用 Expat 分块解析、SQLite 暂存；不加载整份 XML DOM，不把百万条样本放入 `/api/state` 或浏览器内存。按日迭代聚合，数值均值不缓存全量记录；区间统计只保留必要区间。

拒绝 XML 实体、外部 DTD、路径穿越、ZIP 重复名/符号链接/加密 ZIP、过深嵌套、过大属性、非有限/负值、不支持单位、无时区、倒置/未来/超过 48 小时的单样本。数字上界仅用于导入防护，不是医学参考范围。正常 Apple 内部 ELEMENT/ATTLIST DTD 可读。

损坏/安全违规/超限整次失败，不保存部分数据；支持类型中个别无效项会计数显示，用户可以取消整次导入。未知类型按跳过列出。不要因文件过大就在网页或 Python 中关闭全部限额；完整大型档案可先在 Apple/可信导出工具中缩小，或未来实现经测试的分片导入。

## 接入方式的真实边界

本轮交付的是**官方文件导入 → 预览 → 保存 → 趋势/明细 → 实际饮食回顾 → 备份/删除/静态导出**完整闭环。没有原生 iOS App、实时 HealthKit 读取、iCloud 获取或后台自动同步。

自动接入需要原生签名、逐类型权限、增量与删除处理、配对加密及真机测试。不要把一个未经构建验证的 Swift 示例称为已接通。调研依据见 [研究报告](research/2026-11-22-apple-health-integration.md)，测试范围见 [验收报告](ACCEPTANCE-v1.4.0.md)。
